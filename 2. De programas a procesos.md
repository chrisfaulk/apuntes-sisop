
Un programa es estático porque es una serie de instrucciones predefinidas sin estado almacenadas en disco. Un proceso es dinámico porque es la instancia en la que se ejecutan esas instrucciones y evoluciona su estado con el tiempo (PC, registros, recursos)

## Glosario

- **Programa:** conjunto ordenado de instrucciones que pretende resolver un problema.
- **Instrucción:** unidad de ejecución que dura un tiempo finito y se ejecuta sobre un procesador (atómico, no se puede interrumpir)
- **Proceso:** 
	- Es una instancia de un programa cargado en Memoria Central al cual se le asocia un contexto de ejecución (Run Time Environment) mediante un vector de estado o Bloque de Control del Proceso (PCB)
	- Consiste en una secuencia de acciones llevadas a cabo a través de la ejecución de una serie de instrucciones para proveer alguna función del sistema.
	- Tiene direcciones reales/relativas al origen y los syscalls resueltos.
	
- **Programa fuente**: código de alto nivel con direcciones de memoria simbólicas a las que se hace referencia mediante aliases de las variables. Migrable entre entornos y sistemas operativos.
- **Compilación:** traducción del código fuente a lenguaje máquina para permitir que una computadora ejecute un programa
- **Programa objeto:** código máquina resultante de compilar un código fuente. Puede tener direcciones relativas al origen o direcciones de memoria reales dependiendo de la compilación (ej: com y exe) y el sistema operativo. Se puede migrar mientras sea entre mismas arquitecturas y mismos S.O. No tiene resueltas las syscalls.
- **Programa ejecutable:** resultado de haber compilado y link-editado un código fuente. Tiene sus direcciones relativas al origen o reales y sólo es migrable a la misma versión de S.O. y de kernel
- **Link-editor:** programa que toma uno o más archivos de objeto generados por un compilador y los combina para crear un único archivo ejecutable, biblioteca o módulo de carga. Es parte del toolchain de compilación.
- **Loader**: componente/mecanismo/software/porción de código/programa auxiliar del sistema operativo encargado de cargar un programa ejecutable desde el almacenamiento a la memoria RAM y dejarlo listo para ejecutarse.

- **Tarea**: objetivo a realizar por la computadora siguiendo una serie de instrucciones organizadas y agrupadas.
- **Job:** conjunto de tareas similares que se ejecutan en segundo plano de manera ininterrumpida y desatendida. 

- **Thread**: también llamado proceso liviano, es un trozo o sección de un proceso con sus propios registros, pila y PC que puede compartir el espacio de memoria (variables globales, heap, código, file descriptors, sockets, etc.) con aquellos threads que forman parte de su mismo proceso. Un proceso puede o no generarlos.

- **PCB o vector de estado**: estructura de datos guardada en la memoria privada del S.O. Es el origen de la información que se copia desde y hacia la CPU cada vez que se realiza un cambio de contexto. El S.O. utiliza colas con punteros a los PCB para mantener el registro de estado de los procesos. (cola de listos, cola de bloqueados, etc.)
## Flujo

- Se compila un programa fuente (código de alto/bajo nivel con direcciones simbólicas) para transformarlo a un programa objeto (código máquina con direcciones relativas)
- El Link-editor se encarga de resolver las syscalls en las direcciones de memoria donde las guarda el sistema operativo
- El loader carga el programa en memoria:
	- Copia el código y los datos desde el disco
	- Reserva memoria y espacios de dirección para código, datos, stack, heap
	- Resuelve detalles finales como bibliotecas dinámicas
	- Transfiere el control al programa (a su función main)

## Ciclo de vida de los procesos

El ciclo de vida son los distintos estados y su forma de transicionar entre ellos desde que nace hasta que muere un proceso.

### Estados

- Activos:
	- **Listo**: se puede ejecutar. Está cargado en memoria, tiene su PCB creado y todos sus recursos asignados salvo el procesador.
	- **Ejecución**: el proceso está siendo ejecutado en este momento. Sus instrucciones están siendo procesadas en algún procesador. Habrá tantos procesos como procesadores haya.
	- **Bloqueado**: en espera de algún evento para poder continuar su ejecución. Sucede cuando el proceso pide hacer algo fuera de la CPU.

- Inactivos:
	- **Nuevo**: se solicitó al S.O. la creación de un proceso mediante un syscall hecho por una interrupción de hardware a la interfaz de máquina extendida. Está en el módulo Loader, el cual lo carga a MC y le crea su PCB.
	- **Finalizado**: se realizó la syscall de terminación de programa. Existe de dos formas:
		- Normal: el proceso la solicitó
		- Anormal: se produjo por una solicitud externa
	
#### Pseudo estados

Un proceso puede estar en los pseudo-estados "listo suspendido" o "bloqueado suspendido" cuando se le desalojó de la memoria central, ya sea parcial o totalmente. Esto ocurre cuando un proceso en ejecución solicita memoria que no está disponible, por lo que se le retira a estos procesos que hace mucho no ejecutan ninguna instrucción.


#### Ciclo de vida de los Threads

- **Listo**
- **Ejecutando**
- **Finalizado**
- **Bloqueado**

### Cambio de contexto o de estado

Un cambio de contexto o de estado es una operación de hardware que carga los datos del PCB de un proceso al procesador o viceversa y comienza a ejecutar otra rutina. 

### Cambio de proceso

Un cambio de proceso es cuando el S.O. entrega a la CPU un nuevo proceso, debe guardar el estado del proceso que estaba ejecutando y cargar el estado del nuevo. Un cambio de proceso implica un cambio de contexto (se movió el PCB de lugar), pero un cambio de contexto no implica un cambio de proceso (cambio de ejecución entre threads).

### Creación de procesos: 

Todos los procesos son creados por el S.O, pero un proceso puede crear otros procesos a través de una syscall. Cuando un proceso genera a otro, el proceso generador se conoce como proceso padre y el generado como proceso hijo. Estos procesos necesitan comunicarse y cooperar.

#### Tipos de creación

- **Jerárquica**: cada proceso creado es hijo del proceso creador y hereda el entorno de ejecución de su padre. El padre puede continuar ejecutándose paralelamente con sus hijos o esperar a que sus hijos hayan terminado y luego seguir él.
- **No jerárquica**: cada proceso creado por otro proceso se ejecuta independientemente de su creador en su entorno diferente

#### Motivos de creación

- Llega un trabajo nuevo al sistema, por lo que el S.O. debe recibirlo y comenzarlo a ejecutar creando una secuencia de procesos nuevos
- Llega un usuario al sistema, por lo que el S.O. ejecuta el **login**
- Un programa en ejecución solicita un servicio o interrupción, por lo que el solicitante es bloqueado. (Ej: lectura de disco)
- Por razones de modularidad o paralelismo de un proceso existente.

##### Flujo 

- El S.O. asigna un identificador único al proceso
- Se le asigna espacio y se carga en memoria el proceso
- Se inicializa el bloque de control de proceso o PCB
- Se establecen los enlaces apropiados con otras estructuras de datos
- Se amplían o crean otras estructuras de dato en el caso de ser necesarias

#### Muerte de procesos

##### Flujo

- Se liberan los recursos comunes
- Se destruyen los recursos locales
- Desaparece el PCB

##### Tipos

- Terminación en cascada: cuando un proceso muere, también lo hacen sus hijos (normal o anormalmente)
- Daemons o servicios: durante la creación de un proceso, muere el proceso padre y pasa a depender del proceso INIT
- Manual: se termina manualmente por su propietario o un superuser

## Contenido del PCB

- Identificación (única en el sistema)
- Identificadores varios del proceso (dueño, padre, hijos, etc.)
- Estado
- PC
- Registros de CPU y contenidos del caché nivel 2 y 3
- Información para planificación (prioridad)
- Información para administración de memoria (registros base y límite)
- Información de I/O: dispositivos y recursos asignados al proceso, archivos abiertos en uso, etc.
- Estadísticas: tiempo real, tiempo de CPU usado, etc.
- Privilegios
- Otros objetos vinculados al proceso

## Threads

- Los threads poseen una estructura más pequeña llamada TCB (Thread Control Block) que contiene información reducida del PCB, haciendo su cambio de contexto más eficiente.
- Cada hilo posee un TID (Thread IDentifier), un PC, un juego de registros de CPU y una pila
- Podrían considerarse un miniproceso
- Se ejecutan en forma estrictamente secuencial compartiendo la CPU de la misma forma que los procesos. Sólo pueden realizarse en paralelo por un multiprocesador.
- Al igual que los procesos, pueden crear hilos hijos y bloquearse en espera de llamadas al sistema
- Mientras un hilo está bloqueado, se puede ejecutar otro hilo del mismo proceso
- Puesto que comparten espacio de direccionamiento, un hilo puede leer, escribir o limpiar la pila de otro.
- No existe protección entre los hilos del mismo proceso, ya que generalmente cooperan entre sí
- Comparten espacio de direcciones, conjunto de archivos abiertos, procesos hijos, relojes, señales, etc.

### Implementación

Los hilos pueden ser implementados en dos niveles por la forma en que son generados y tratados:

#### Nivel usuario (ULT - User Level Thread) (Green Threads)

En esta implementación, todo el trabajo del hilo es manejado por la aplicación y no son administrados por el kernel. 
Cualquier aplicación puede ser programada para ser multithreaded mediante el uso de threads library, y la generación de los ULT se hace en el momento de compilación. El kernel continúa con la planificación del proceso como unidad y le asigna un solo estado de ejecución (listo, corriendo, etc.), pero nunca se entera de la existencia de estos hilos.

##### Ventajas

- El cambio de hilo no requiere el modo kernel
- El proceso no cambia al modo kernel para manejar el hilo
- El algoritmo de planificación puede ser adaptado sin molestar la planificación del S.O.
- ULT puede correr en cualquier S.O.
- Es muy rápido para la ejecución
- No necesita mecanismos de IPC (comunicación entre procesos) para comunicarse con otros threads del mismo proceso

##### Desventajas

- Cuando se ejecuta un syscall bloqueante, bloquea todo el proceso en caso de que no se use Jacketing (postergación de la operación de I/O hasta que el proceso sea desalojado o hasta que todos los threads quieran hacer I/O).
- Una aplicación multithreaded no puede tomar ventaja del multiprocesamiento porque el kernel asigna un proceso a un sólo procesador a la vez
#### Nivel kernel (KLT - Kernel Level Thread)

Todo el trabajo de manejo de hilos es hecho por el kernel, por lo que no hay código de manejo de hilo en el área de la aplicación. Todos los hilos dentro de una aplicación son soportados dentro de un solo proceso, pero el kernel mantiene la información de contexto para el proceso e individualmente para los hilos de cada proceso.

##### Ventajas

- Simultáneamente el kernel puede planificar múltiples hilos del mismo proceso en múltiples procesadores
- Si un hilo de un proceso se bloquea, el kernel puede planificar otro hilo del mismo proceso
- Las rutinas mismas del kernel pueden ser multithreaded

##### Desventajas

- La transferencia de control de un hilo a otro dentro del mismo proceso le requiere al kernel un cambio de modo
