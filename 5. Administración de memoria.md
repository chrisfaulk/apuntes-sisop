
# Conceptos

- La MC es el único espacio de memoria al que accede el procesador.

- Los caché no son considerados otro espacio de memoria porque sólo replican el contenido de la MC.

- Los registros del procesador tampoco son considerados espacio de memoria porque son muy pequeños y sólo se utilizan para tareas propias internas del mismo procesador.

- Los discos son espacios de memoria secundarios y no son accesibles directamente por el procesador, están conectados mediante el módulo de I/O.

- Para ejecutarse, un proceso debe estar cargado en MC. Si se debe cargar completo, depende del hardware y de la técnica de administración de memoria utilizada.

- El espacio desperdiciado al cargar en una partición de memoria un proceso que no la ocupa completamente se denomina fragmentación interna

# Funciones y operaciones del administrador de memoria

## Espacio de direccionamiento

La memoria es un arreglo unidireccional de bytes y cada operación de lectura/escritura se hará de a 8 bits.

Un procesador que soporta un espacio de direccionamiento de n bits puede referirse directamente a hasta $2^n$ bytes.

## El MMU

Un Memory Manager Unit o Unidad de Administración de la Memoria es un módulo de hardware asociado al procesador que permite realizar muchas tareas relevando al S.O. de realizarlas para mejorar la performance. Su tarea principal es resolver cómo ubicar los programas en la memoria física disponible.

El S.O. es el encargado de asignarle un espacio de memoria a cada proceso al ejecutarlo, pero el MMU es el encargado de validar que ningún proceso haga referencia a un espacio de memoria que no le corresponde mediante el hardware. Al delegar esta tarea al hardware, se evita tener que hacer el context switch de cargar el S.O. al procesador cada vez que se deba validar esta condición.

Cada vez que un proceso intenta acceder a memoria, el MMU valida que esa referencia esté dentro del rango de direcciones que le corresponde al proceso. De no ocurrir, arroja una excepción de hardware interno.

Cuando se está ejecutando un proceso, los datos de su dirección de memoria base y límite están guardados en el procesador. Esta información de los procesos que están cargados en memoria pero no están actualmente ejecutándose, se guarda en el PCB.

## Espacio de memoria de un proceso

Cuando se carga un proceso en memoria, el planificador de largo plazo le asigna un espacio de direcciones para cargarlo. Esta carga puede ser parcial o total.

El S.O. separa el proceso en cuatro secciones diferentes: 

- Sección de código o texto: área de solo lectura donde se carga el ejecutable. Habitualmente son las posiciones más bajas del espacio de memoria asignado al proceso
- Sección de datos: espacio fijo preasignado para las variables globales y datos inicializados. Se fija en tiempo de compilación y no cambia, aunque los valores de esas variables sí pueden cambiar. Ej.: cadenas de caracteres.
- Área de espacios libres o HEAP: espacio para la memoria dinámica de memoria durante la ejecución del proceso. Se ubica por encima de la sección de datos, y crece hacia arriba.
- Pila de llamadas o STACK: espacio de memoria que se usa para almacenar la secuencia de funciones que han sido llamadas dentro del proceso con sus parámetros, direcciones de retorno, variables locales, etc. Ocupa la parte más alta y crece hacia abajo.

## Resolución de direcciones

El compilador reemplaza las variables/funciones simbólicas por las direcciones de memoria a donde se ubican. Para que un proceso pueda coexistir con otros, esas direcciones deben ser traducidas a posición relativa al origen, con alguna de las siguientes estrategias:
- **En tiempo de compilación**: las direcciones son absolutas/fijas ya que están asignados a espacios físicos de la memoria.
- **En tiempo de carga**: el loader calcula las ubicaciones al momento del inicio del programa (reg. base + offset). La posición física asignada se mantiene durante toda la ejecución y se vuelve asignar con cada inicialización del proceso.
- **En tiempo de ejecución**: al cargar y ejecutar un proceso, el mismo asigna direcciones lógicas a cada porción diferenciable del código. Al momento de tener que referenciar una de estas porciones, el MMU traduce esa dirección de lógica a física para que el S.O. pueda acceder a ella. Una posición de memoria puede cambiar entre accesos incluso durante una misma ejecución.

# Asignación de memoria contigua

## Para sistemas monoprogramados

Ya que sólo permiten un proceso cargado simultáneamente en la MC, el S.O. casi no necesitaba gestionar la memoria.

Divide la memoria en área de S.O. (ubicado en las posiciones más bajas de memoria) y área de usuario mediante el boundary register.

Solo permite ejecutar procesos que quepan totalmente en el espacio disponible de memoria.

Son muy performantes porque su única validación necesaria es que la referencia de memoria de un proceso usuario esté por encima del registro límite.

## Para sistemas multiprogramados

### Particiones fijas

Se parte la memoria en espacios fijos predeterminados al configurar el sistema (son reconfigurables, aunque es complicado). 

Cada partición indica cuántos procesos simultáneos pueden estar cargados.

### Particiones variables

Al cargar un proceso, se crea una partición del tamaño de ese proceso. 

Los espacios se crean de manera contigua, pero pueden quedar espacios libres en medio de particiones al finalizarlos. Esto se llama fragmentación externa (porque no está dentro de ninguna partición) y puede solucionarse con una defragmentación o compactación, que implica reubicar la memoria de los procesos una a continuación de la otra (muy costoso).

El S.O. tiene una lista de los espacios de memoria disponibles con su repectivo tamaño.
Cuando llega un nuevo proceso, se determina en qué hueco disponible de memoria se debe cargar utilizando una de tres técnicas de asignación:

- **First fit**: carga el proceso que llega en el primer hueco donde quepa. Técnica más performante.
- **Best fit**: técnica con mayor optimización de espacio. Carga el proceso en el hueco más chico donde el proceso quepa.
- **Worst fit**: carga el proceso en el hueco más grande donde quepa para aprovechar mejor el espacio. Es una contrapropuesta directa de best fit.

Estas tres técnicas necesitan que todo el proceso esté en un espacio contiguo. Son pensadas para resolución de direcciones en tiempo de carga. Son vulnerables a la fragmentación.
