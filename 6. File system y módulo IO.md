
El file system es la forma en la que el S.O. le presenta al usuario la información, sus datos, programas y demás cosas guardadas en la computadora. 
El módulo genérico de I/O es quien tiene que ver cómo recuperar la información almacenada. La forma de recuperar la información depende del hardware y la forma donde estoy almacenando dicha información.

La unidad de trabajo del FS es el archivo, la del módulo genérico de I/O es el sector o bloque de datos. 

La relación de archivos a bloques siempre va a ser 1 archivo a N bloques de datos, nunca viceversa. 

Decimos que estamos trabajando sobre lo mismo porque, como usuarios del S.O., no nos interesan los sectores o bloques de datos, nos interesan los archivos y los directorios o carpetas.

Los directorios o carpeta son simplemente una herramienta de organización que me da el S.O. para organizar mis datos, no tiene que ver con la ubicación física.

Del lado del usuario (el file system), existe una única dimensión. Esto cambia en el espacio físico, donde, dependiendo del hardware, puede existir más de una dimensión.

El tamaño máximo del File System lo da la cantidad de bits direccionables por la FAT y el tamaño de bloque que defina. 

# Funciones de File System

1. Gestionar espacio ocupado: saber qué está ocupado y por qué
	1. FAT (File Allocation Table): guarda indirecciones de un determinado archivo
	2. i-Nodos
	3. B-trees
	4. HPFS
2. Gestionar espacio libre
	1. Bit vector: Forma de llevar el espacio libre en FS tipo FAT. El método de formateo FAT era una mezcla de la FAT para el espacio ocupado + un bit vector para espacio libre + X para estructura de directorios. Tiene tantos bits como sectores lógicos el disco.
	2. Lista enlazada de bloques libres
	3. Bloque de direcciones libres: igual que el anterior, pero anota las direcciones lógicas libres.
	4. Bloque de direcciones libres continuas: igual que el anterior, pero lo hace con dirección base libre + cantidad de bloques contiguos libres
3. Brindar la estructura de directorios
	1. Árbol n-ario: soporta soft links (referencias lógicas de una parte del FS a otra. Ej.: acceso directo de windows apuntando al nombre de la ruta del archivo).
	2. Grafos acíclicos: soporta hard-links (referencia física al i-nodo de lo que se está referenciando. No ocupa espacio en disco.) y soft-links

Todo esto se encuentra en el área de directorios.

# Funciones de módulo IO

1. Administrar el hardware del mundo asincrónico (driver)
2. Buffering de datos (almacenamiento intermedio para equiparar velocidades, evitar datos erróneos)
3. Comunicación con el procesador (interrupciones de hardware externas)
4. Detección y manejo de errores (el driver realiza segundas lecturas o informes de error)

# Tipos de IO

- E/S programada: no permite la multiprogramación. El hardware no tenía inteligencia, el módulo IO era muy básico y no tenía procesador específico. El procesador hacía todas las tareas de entrada y salida. 
- E/S por interrupciones: nace la multiprogramación. El procesador hace la IO y otro procesador central ejecuta las instrucciones. Se necesita de vector de interrupciones, FLIH o SLIH para que el procesador se entere que está pasando algo en el mundo externo.
- E/S por DMA:
	- Ráfagas: prioridad transferencia entre I/O y memoria
	- Robo de ciclos: prioridad CPU
	- Transparente: prioridad CPU, I/O solo utiliza si está libre

# Tipos de dispositivos

## Discos rígidos

Un disco rígido está formado por un disco céntrico con distintos platos o caras magnéticas con cabezas lectora-grabadoras conectadas a un puente de cabezas. Todas las cabezas se mueven en conjunto (como estándar, pero hay algunos que implementan movimiento autónomo o más de un puente). Siempre se busca minimizar el movimiento de las cabezas.

Tiene distintas piezas:

- **Sector**: bloque individual de una circunferencia del disco
- **Pista**: circunferencia del disco
- **Cilindro**: vista lógica de las pistas (Ej.: suma de todas las pistas 0 de todos los discos)

Todas las pistas tienen la misma cantidad de sectores y todos los sectores graban la misma cantidad de datos.

Un disco sólo puede leer o escribir información si está en su velocidad establecida de, por ejemplo, 5400 o 7200 RPM. Al frenar el disco para evitar su desgaste y volverlo a iniciar, hay un tiempo de overhead hasta que la rotación vuelve a llegar a dicha frecuencia.

Existen tiempos de E/S. 

El orden es:

1. Espero que la cabeza lectora se ubique sobre la pista que corresponda (seek time)
2. Espero que la rotación del disco lleve la cabeza lectora hacia el sector que quiero leer (rotational delay time)
3. Tiempo de transferencia (Lectura o escritura, lleva la información hacia el buffer de la controladora)
4. Tiempo de armado y formateado de datos (verifica que los datos sean mínimamente correctos y procede o corta la comunicación/vuelve a leer)
5. Tiempo de controlador o canal (tiempo que pasa la información en la unión del disco rígido con el módulo de I/O)
6. Tiempo de llenado de buffers
7. Tiempo de transferencia de datos
8. Tiempo de acceso a MC
9. Tiempo de escritura en MC

Cuando se formatea un disco o una partición en NTFS, al armar la tabla de directorios, el sistema pone dos bloques de datos dentro de la estructura. Cuando creo un archivo, si el mismo es lo suficientemente chico como para entrar en uno o dos bloques, el mismo va dentro de la tabla de directorios. Si ocupa más, arma un B-tree hacia abajo primero con el bloque 2 (el 1 queda como tabla de direcciones).
